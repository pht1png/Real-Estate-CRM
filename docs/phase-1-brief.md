# Phase 1 brief — Real Estate CRM (sales core)

Put this file at `docs/phase-1-brief.md`. It is the source of truth for Phase 1. If the code and this brief disagree, stop and ask.

## 1. Product in one paragraph

A multi-tenant SaaS CRM for Thai housing developers (condo and low-rise) with several projects. Two pipelines: a **lead** is a customer's enquiry about a project (never a unit), vetted by the salesperson; when the customer **actually visits** the showroom it converts into an **opportunity**, where a unit is chosen at deposit (จอง). Phase 1 is the **sales core**: capture every enquiry with a source, route it to a project pool, make salespeople contact it the same working day, follow up after every site visit, and trace it through deposit (จอง), contract (ทำสัญญา) and transfer (โอน). The first customer is the founder's family business; every rule is a per-company setting with a default.

## 2. Phase 1 definition of done

- A salesperson can log a walk-in on a phone in under 30 seconds.
- Every lead has a source (and campaign when known) and a consent record.
- Two pipelines (lead → opportunity). **Lead (vetting):** enquiry → pool → claim (or owned at once when a salesperson logs it) → attempting contact → connected → qualified (the salesperson confirms budget, timing, unit types and intent), with Disqualified (reason) / Nurture exits. **Conversion:** only a confirmed showroom visit of a **qualified** lead (an unqualified walk-in is qualified face to face during the tour, then converted) (a walk-in, or a booked tour that actually happened). **Opportunity:** visited (repeatable) → negotiating (unit selection) → deposit (จอง) → contract (ทำสัญญา) → waiting for mortgage result (mortgage buyers) → transferred (โอน), with a Lost (reason) exit.
- Deadlines and follow-ups are enforced automatically; nothing sits without a next step.
- Managers see what is stuck; executives see deposits, contracts and transfers vs target.
- One company can never see another company's data.
- Thai is the default UI language; English is switchable.

## 3. Stack and conventions (fixed decisions)

- **Scaffold:** Better-T-Stack with a Next.js web app (`apps/web`) and a separate Hono API server on Bun (`apps/server`), tRPC, PostgreSQL (Docker locally), Drizzle, Better Auth, Turborepo, Biome, Husky, skills addon, Bun as package manager. Follow the scaffold's folder layout; don't restructure it.
- **Where code runs:** all business logic, tRPC routers, Better Auth, webhooks, push sending and scheduled jobs run on the Hono server. The web app is UI only and calls the server through tRPC and the Better Auth client.
- **Auth:** Better Auth email + password, password reset by email, invitations, organization plugin (one organization = one developer company). Two-step login (Better Auth two-factor plugin) is optional for every user.
- **Cross-origin auth:** web and server are different origins. Configure CORS with credentials and Better Auth `trustedOrigins` for local dev (two ports). In production the apps live on subdomains of one domain (e.g. `app.` and `api.`) with cross-subdomain cookies. Keep URLs in env vars, never hard-coded.
- **Tenancy:** every tenant table has `organization_id`. The organization comes **only** from the session's active organization on the server, never from client input. Every query filters by it. Child rows reference parents by `(organization_id, id)` where practical.
- **Business logic** lives in service functions called by tRPC procedures; React components never contain business rules. Every mutation: check permission → validate input with Zod → run in a DB transaction → write an audit entry if sensitive.
- **Migrations:** `drizzle-kit generate` + `migrate`, committed to git. No `db:push` against any shared database (replace the scaffold's push script for anything beyond local throwaway use).
- **Money** as integer satang (`bigint`). **Time** stored as UTC `timestamptz`; office hours, closed dates and "working day" are computed in each project's time zone (default `Asia/Bangkok`).
- **Phones** normalised to E.164 (`+66…`) before storing or matching.
- **i18n:** all user-facing strings via `next-intl` messages (`th`, `en`), Thai default. Display Buddhist-era dates in Thai locale; store Gregorian.
- **UI:** shadcn/ui + Tailwind; mobile-first for salesperson screens; desktop-first for manager and executive screens.
- **Tests:** `bun test` for services against a real Postgres (Docker), Playwright for the critical journeys listed in milestones. Every service gets at least one cross-tenant test (org B cannot read or change org A's data).
- **Scheduled work** (claim expiry, reminders): an in-process scheduler in the Hono server every 5 minutes, guarded by a Postgres advisory lock so only one server instance runs each job, plus lazy checks when data is read. No extra queue infrastructure in Phase 1.
- **Database driver:** a standard Postgres driver that supports interactive transactions (deposits need a row lock). Don't use an HTTP-only serverless driver.
- **File storage:** floor plan images and import files go to S3-compatible object storage (e.g. Cloudflare R2) behind a small storage interface; local dev may use a local folder. Images are served through signed or public-read URLs, never through the database.
- **Deployment (after M1, not now):** web on Vercel, API server on a long-running host (e.g. Railway, Fly.io or Render) in Singapore, database on managed Postgres (e.g. Neon) in Singapore. Migrations run before the new server version goes live.

## 4. Roles and permissions (Phase 1)

Roles are **a role plus a scope** (the projects a member covers), not hard-coded job titles. Each company can rename role labels (e.g. "Head of sales" for a sales manager covering all projects). Marketing roles come in Phase 2; the service role returns with the handover module; team leaders and sales admin are added only when a customer needs them.

| Role                                                   | Sees                                                                                                                                   | Can do                                                                                                                                                                                           |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Salesperson                                            | Own leads and opportunities + pool in their projects; one summary line for the same contact's leads in other projects; own commission estimates | Create and qualify leads, claim, log activities, book and record visits, change status, record deposit and contract signed, mark Lost / Nurture / Invalid                                                |
| Sales manager (scope: a set of projects, possibly all) | Everything in the projects they cover, incl. team commission estimates                                                                 | Assign / move any lead, bulk reassign, merge duplicates, split targets, edit unit prices and block / unblock units, record contract signed, mark opportunities Transferred or Cancelled, export (logged) |
| Executive                                              | Everything                                                                                                                             | Set project targets, export (logged)                                                                                                                                                             |
| Admin                                                  | Settings                                                                                                                               | Users, projects, unit lists, sources, campaigns, rules, integrations                                                                                                                             |

Cross-project rule: the **contact profile is shared** (name, phones, LINE ID, email, consent); each **lead and its opportunity are private** to their owner, the managers covering that project, and executives. Other salespeople see only: project · lead or opportunity status · owner.

Database guarantees:
- One lead per contact per project (`unique(contact_id, project_id)`), and at most one live opportunity per lead (partial unique index; a lost opportunity can be followed by a new visit).
- A salesperson's scheduled appointments never overlap (exclusion constraint on member and time range).
- A phone number belongs to one contact per organization (`unique(organization_id, phone_e164)`).
- At most one non-cancelled deposit per unit (partial unique index on `deposits(unit_id)` where status is `deposited`, `contracted` or `transferred`), plus a row lock on the unit inside the deposit transaction.
- History is append-only: status changes, assignments, merges, contracts, transfers and cancellations are activities or audit entries, never overwrites.

## 6. Business rules and defaults

All of these are per-organization settings with these defaults.

| Rule                | Default                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quick capture       | Salespeople and managers log every enquiry: name, phone, project, source (+ campaign if known), marketing consent tick. Nothing else required. An enquiry a salesperson logs themselves (a walk-in, or a call they took) is **theirs at once**: no pool and no contact deadline, but it needs a next follow-up. A walk-in who is touring now is recorded with Confirm visit on the customer page. A manager logging an enquiry picks an owner or sends it to the pool. If the duplicate check finds an existing lead in that project, the re-enquiry rule decides the owner instead. Every manually logged lead has a **Received at** time (default now; never in the future; at most 30 days back). Sources in an in-person channel (walk-in, event) require budget range, buying timeline, unit types wanted and buyer intent at capture |
| Pre-score           | If a Facebook form's budget overlaps the project's price range and the timeline is ≤ 3 months, the lead is **priority**: sorted first in the pool and alerted immediately. Salespeople do the real qualification at Contacted                                                                                                                                                                                                                                                                                                                                                                                          |
| Duplicate check     | Phone matched across the organization as it is typed. Same contact + other project → new lead. Same contact + same project → `enquiry` activity on the existing lead, then the re-enquiry rule                                                                                                                                                                                                                                                                                                                                                                                                               |
| Re-enquiry          | Back to the owner if they contacted the customer in the last 90 days; otherwise to the pool. Logged as `re_engagement` with the campaign if any                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Claim               | First salesperson to claim; max 5 uncontacted claims per person                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Working days        | Each project's office hours per weekday, minus its closed dates (holidays the admin marks per project; some show offices stay open on holidays). Contact deadlines and claim expiry count working time only                                                                                                                                                                                                                                                                                                                                                                                                            |
| Contact deadline    | Before office close on the same working day. Leads arriving or claimed after hours start the clock at next opening. If fewer than 2 office hours remain at claim time, the deadline rolls to the next working day's close. Missed → back to pool, activity logged                                                                                                                                                                                                                                                                                                                                                      |
| Qualified           | The salesperson marks it (being reached is not qualified): budget range (shown against the project's price range), buying timeline, unit types wanted (from the project's types), buyer intent (own stay / investment). **Required before converting** |
| Qualification check | The system assesses fit (fits / too early / budget doesn't fit / not enough details) from the budget against the project's available price range (± the project's tolerance) and the timeline (within the project's qualify window), and suggests a one-tap step: Mark qualified / Move to nurture / Disqualify (budget doesn't fit). A project can switch on auto-qualify for leads that fit; disqualifying is never automatic |
| Site visit          | In person only. **Appointments** are booked for connected or qualified leads (a first tour) and open opportunities (a follow-up visit); 60 minutes by default, never overlapping the salesperson's other appointments. **Reschedule** moves the same appointment (not a cancel); **Cancel** needs a reason. On the day: Arrived records the visit (an unvetted guest is qualified face to face first), Didn't come needs a next follow-up; still open 2 hours after its time → "did they come?" on To do (push reminders in M8). The first confirmed visit converts a qualified lead into an opportunity (Confirm visit or Arrived); the visit time can't be in the future |
| Repeat visits       | Every visit is recorded the same way (Record visit for a walk-in, or Arrived on a follow-up appointment); status stays Visited (or Negotiating); visit count increments |
| After every visit   | A future next follow-up is required (any date) |
| Open leads and opportunities | Always have a next follow-up date (leads new → qualified; opportunities visited / negotiating) |
| Nurture             | Wrong timing: the lead goes to the **nurturing pool** (a Pool tab, told apart by status), unowned and claimable by any salesperson; the previous owner stays in the history. A claim reopens it as Attempting with a contact deadline; a new enquiry reopens it as New. No check-in schedule |
| Unreachable         | 3 `no_answer` activities over 7 days (since the last real contact) → suggest Disqualify (Unreachable) or Nurture; salesperson confirms |
| Disqualify reasons  | Lead phase: invalid data / wrong number, spam, duplicate, agent / competitor, job seeker, budget doesn't fit, location doesn't fit, unreachable, other (write your own reason). A reason is always required. Disqualified leads leave the funnel; not counted as Lost |
| Lost reasons        | Opportunity phase (after a visit): bought from a competitor, bank loan rejected, changed mind, product doesn't fit, postponed, other (write your own reason). A reason is always required |
| Hot / warm          | On open opportunities, computed on read (temp-v1). Signals: visited, buying ≤ 3 months, budget overlaps the project's price range (from available units, ± tolerance), paying cash (mortgage readiness joins in M6b). Warm = 2–3 signals; Hot = all 4, or warm + a second visit. Hot or warm with no activity for 3 days → stale on To do |
| Deposit             | Pick an **available** unit in the lead's project (filter by section, type, price, facing, tags; search by unit number), date, booking fee (เงินจอง), net price (list − discount), promotion note, main buyer + co-buyers. The list price at that moment is stored on the deposit. Second attempt on the same unit fails with "Already deposited by <name> at <time>"                                                                                                                                                                                                                                                |
| Price changes       | Sales managers can edit list prices and block / unblock units in their projects; every price change is kept in price history; existing deposits keep their price                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Contract            | Due 14 days after the deposit date. The deposit's owner or a sales manager records Contract signed: date and contract amount (เงินทำสัญญา); the unit becomes Contracted. Not signed by the due date → owner and managers alerted daily until it is signed or cancelled                                                                                                                                                                                                                                                                                                                                                   |
| Transfer / cancel   | Sales manager marks a contracted opportunity (or one waiting for the mortgage result) Transferred (date), or cancels one at either status (reason: contract not signed, mortgage rejected, buyer changed mind, buyer unreachable, other). The status it was cancelled at is stored. Cancelled → unit available, opportunity to Lost (the lead reopens on a new enquiry)                                                                                                                                                                                                                                                                                                                           |
| Commission estimate | Project % × net price; credited to whoever records the deposit; visible to that salesperson and their managers; removed on cancel; labelled "estimate"                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Manager override    | Assign or move any lead any time; reason required; logged                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Offboarding         | Disabling a member ends sessions and moves their open leads to the manager's queue                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Merge duplicates    | Sales managers only; keeps all leads, activities and deposits; logged                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## 7. Screens (Phase 1)

- **Salesperson — Overview** (phone first): two sections. **Leads** (blue): my leads per status (new, attempting, connected, qualified), this month (received, converted, disqualified) and rates (contact, qualify, lead → opportunity). **Opportunities** (green): my opportunities per status (visited, negotiating, deposited, contracted, waiting for mortgage result), hot / warm counts, this month (visits, deposits, won, lost), rates (visit → deposit, win rate) and closed-won this month (count; volume and commission estimate once deposits exist). Reasons are analysed by managers (M7).
- **Salesperson — To do** page with a count badge: showroom arrivals today (qualified vs unvetted first tours, and follow-up visits; Arrived / Didn't come / Reschedule / Cancel), due today (leads and opportunities), and stale / overdue (appointments nobody closed after 2 hours, missed follow-ups, missing follow-ups, unreachable, hot / warm gone quiet). Lead cards are blue and opportunity cards green, with the type badge top left and attributes aligned like a table. Each card: Call (dialler + result: Answered / No answer / Wrong number, then the next follow-up), LINE, and a ⋯ menu; a Start mode walks the list one lead at a time. Later: contracts due in the next 3 days (M6).
- **Pool** page: unclaimed leads in my projects (priority first) with Claim; its sidebar item shows a red count of leads waiting.
- **Quick capture** form; **contact page** (shared profile, this lead's timeline and referrer, other-project summary lines, co-buyers, project price range next to budget); one-tap actions: Call, No answer, LINE note, Book appointment, Confirm / Record visit, Funding, Record deposit, Record contract, Lost, Nurture, Invalid.
- **Manager board:** open leads by status and owner, overdue follow-ups, claimed vs contacted, median time to first contact, "Don't know" source share per person; assign / reassign / bulk reassign; merge duplicates; deposits awaiting contract (overdue first) and contracts awaiting transfer; targets split per salesperson; export (logged).
- **Units (manager):** unit grid per project grouped by section (and floor for buildings), coloured by status; filter by type, price, facing, tags; edit price (with reason) and block / unblock.
- **Executive:** deposits and transfers vs target per project this month, plus contracts signed; deposit → contract → transfer rates and cancellation reasons by status; hot pipeline count.
- **Admin settings:** members, roles, role labels and project scopes; projects, office hours and closed dates; sections; unit types with floor plan images; project unit tags; unit import (Excel/CSV with preview and row errors); channels and sources; campaigns (minimal); rules from section 6; integrations.
- **Notifications** page + badge.

## 8. Notifications

- Web push from an installable PWA (manifest + service worker in `apps/web`, VAPID keys), sent from the API server at any hour; in-app notifications as fallback. On iPhone, push requires the app on the Home Screen, so onboarding shows that step.
- Events: new lead in my pools, lead assigned to me, claim about to expire, follow-up due, visit reminder, visit outcome needed, contract due tomorrow or overdue (owner + managers), contract awaiting transfer (managers), a salesperson's follow-ups overdue (managers, admins, owners), a salesperson below KPI (managers, admins, owners; KPIs and thresholds set per company in M7).

## 9. Lead intake integration

- A **signed inbound webhook** on the API server, per organization (secret token), that accepts a lead (name, phone, budget, timeline, project code, campaign code, source). Used first by a connector tool (Make / Zapier) forwarding Meta lead-form submissions, so Facebook leads arrive within minutes.
- Native Meta Lead Ads webhook comes later in Phase 1 only if time allows; otherwise Phase 2.
- Inbound leads go through the same duplicate check, get the pre-score from section 6, and land in the project pool with source Online → Facebook and the campaign matched by code.

## 10. PDPA and audit

- Consent tick records who ticked and when.
- Admin can export one contact's data or anonymise them.
- No national ID numbers, ID card images or income documents. Income is stored only as an optional **range** on the lead (private to its owner and managers, never in summary lines); an exact income (the M6b calculator) stays in the browser.
- Audit log: assignments, overrides, merges, deposits, contracts, transfers, cancellations, exports, role and setting changes. Audit payloads hold IDs, not personal data.
- Exports: sales managers and executives only, scoped to their projects, always logged.

## 11. Out of scope for Phase 1

Marketing module (budgets, spend, reports, promotions catalogue, Facebook audiences, marketing and agency roles), service role and handover/defects, team leaders and sales admin roles, multiple sources per lead, quotes, down-payment (ผ่อนดาวน์) schedules and payment tracking, LINE OA integration, unit holds, email marketing, AI qualification, self-serve sign-up.

Phase 2 candidate (decided during M3): a predictive lead score trained on Phase 1 history. Phase 1 prepares for it by keeping scoring in one versioned function, snapshotting the inputs known at lead creation, and recording outcomes as append-only activities.
